00 / FOUNDATIONS

What does a complete PPC establish?

A roadmap for arguing that an algorithm does what its specification requires.

THE CENTRAL CONTRACT
∀x ∈ D : Terminates(A,x) ∧ Q(x,A(x))

For every valid input x, the algorithm A must terminate, and its output must satisfy the required relation Q. The specification defines Q; a proof establishes it.

Four passes, each with a distinct job

P1 · DEFINESpecification

Which inputs are valid? What exact output relation defines correctness?

P2 · CONSTRUCTAlgorithm

Describe a precise sequence of state changes and termination.

C · JUSTIFYProof

Establish why the algorithm terminates and satisfies the output relation.

K · ACCOUNTComplexity

Derive time and extra memory bounds under a stated cost model.

How to use the field manual

  1. Read the statement and separate input assumptions from the target conclusion.
  2. Write the mathematical specification before choosing an algorithm.
  3. Design an unambiguous procedure and choose an appropriate proof technique.
  4. Show correctness, termination, and any feasibility/optimality obligation.
  5. Derive complexity and review edge cases before submission.
Evidence is not all the same

The site stores your prose PPC; it does not automatically validate its mathematics. A structural check, bounded tests, human review, and a Lean-checked theorem offer different evidence, and the subject of each check must be identified.

01 / PROBLEM SPECIFICATION

Define exactly what must be true.

A precise specification is an output contract, not a retelling of the story.

THE MATHEMATICAL MODEL
P = (X, Y, D, Q, K)

X: input type. Y: output type. D ⊆ X: admissible input domain. Q(x,y): required relation. K: computational cost model.

Define each ingredient

Input domain D
Specify lengths, value ranges, indexing conventions, duplicates, graph properties, and any preconditions. Do not silently assume an array is sorted.
Output type Y
Integer, Boolean, permutation, set, path, sequence, or a sentinel for impossible inputs? Define its representation.
Required relation Q
State exactly when y is accepted as an answer for x. For optimization, require feasibility and a comparison against every feasible candidate.
Quantifiers
∀ means every; ∃ means at least one. Where existence is claimed, define the witness or explain why a witness must exist.

From vague to mathematically precise

TOO VAGUE

“Find the missing number in the array.”

WELL-SPECIFIED

For an integer array A, output the unique m ≥ 1 such that m ∉ A and every integer k satisfying 1 ≤ k < m belongs to A.

The second statement specifies the smallest missing positive integer, including when A contains negative values and duplicates.

P1 checklist

  • All input assumptions and constraints stated?
  • Output type and acceptable values specified?
  • Infeasible or empty instances addressed?
  • Optimality quantified if the problem asks for a minimum or maximum?
02 / PROPOSED ALGORITHM

Make each step unambiguous.

Another reader should be able to execute your procedure without guessing what you meant.

ABSTRACT ALGORITHM
A = (Σ, Init, Step, Halt, Out)

Describe the state Σ, initialization, transitions, halt condition, and extracted output. Pseudocode is welcome but not required.

Five questions your procedure must answer

  1. Initialization: What variables and data structures exist initially?
  2. Transition: What is examined and updated on each step?
  3. Choice rule: How is one action selected if several are possible?
  4. Stopping condition: When, precisely, is processing finished?
  5. Output: What is returned for every type of valid instance?

Illustrative procedure — interval sums

Input: A[0..N−1], queries (l,r)
pref[0] ← 0
for i from 0 through N−1:
    pref[i+1] ← pref[i] + A[i]
for every valid query (l,r):
    output pref[r+1] − pref[l]

This is a complete procedure, but it still needs a proof of its prefix invariant and the subtraction identity.

Implementation claims require extra care

A proof over unbounded mathematical integers does not automatically verify Java int. Consider overflow, indexes, input parsing, memory limits, and the exact behavior of built-in operations.

03 / CORRECTNESS PROOF

A claim needs a chain of reasons.

Show the postcondition holds for every valid input, not merely the cases that feel typical.

TOTAL CORRECTNESS
Partial correctness + Termination = Total correctness

Partial correctness: if execution finishes, its result satisfies Q. Termination: every permitted execution finishes. Total correctness requires both.

What you must prove

01Well-definedness

Operations are legal in all reachable states.

02Main lemma or invariant

The relationship between your intermediate state and the specification.

03Termination

A finite bound or strictly decreasing rank in a well-founded order.

04Postcondition

At exit, the algorithm's result satisfies Q.

05Optimality where required

The solution is feasible, and no feasible competitor is better.

Loop invariant: four obligations

INITIALIZATIONI(s₀)
PRESERVATIONI(s) ∧ guard(s) ∧ Step(s,s′) ⇒ I(s′)
EXITI(s) ∧ ¬guard(s) ⇒ Q(input,Out(s))
TERMINATIONVariant(s) ∈ ℕ; decreases every continuing step

A common logical gap

NOT SUFFICIENT

“I process all elements, so the answer is optimal.”

WHAT IS MISSING

The invariant and its proof, exit implication, termination, and an argument for optimality if optimization is claimed.

04 / STRATEGY SELECTOR

Pick a proof that fits the algorithm.

Use the selector to see technique-specific obligations, common failure modes, and proof skeletons.

Watch for these anti-patterns

Testing as proof

“All examples pass.” Finite examples are useful for detecting errors, but they cannot justify an unrestricted universal statement.

Circular argument

“Greedy is optimal because it always picks the best.” The conclusion is merely being repeated.

Local-to-global leap

“My choice is locally best, therefore the whole solution is best.” A separate exchange or structural theorem is needed.

05 / RESOURCE ACCOUNTING

Account for every operation.

An asymptotic bound should follow from the procedure and an explicit computational cost model.

ASYMPTOTIC UPPER BOUND
T(N) ∈ O(f(N)) ⇔ ∃c > 0, N₀ : ∀N ≥ N₀, T(N) ≤ c · f(N)

O is an upper bound; Θ is a tight asymptotic bound. State what N measures and which operations count as constant-cost.

Common bounds and their justification

PatternTimeReason
One full scanO(N)Each value inspected a bounded number of times.
Sort + scanO(N log N)Sorting dominates one linear pass.
Two full nested loopsO(N²)Up to N inner steps per N outer steps.
Binary searchO(log N)Remaining interval shrinks geometrically.
Prefix + Q queriesO(N+Q)Preprocess once, answer each query in constant time.
BFS adjacency listO(V+E)Vertices and edges considered bounded times.

Auxiliary space

Explicitly state whether your bound includes the input. A prefix array costs O(N) extra space; a fixed number of counters costs O(1). Include recursion stacks and data structure overhead when relevant.

Implementation-specific costs matter

In Java, Arrays.sort, HashMap, copying arrays, and concatenating immutable strings can dominate the complexity. Distinguish average/expected costs from guaranteed worst cases.

07 / COMPLETE WALKTHROUGH

A full PPC, from start to finish.

A worked prefix-sum example unrelated to your unresolved ARDS challenges.

WORKED CASE · INTERVAL SUMSum a contiguous range.

Given an integer array A with N ≥ 1 and valid inclusive indices 0 ≤ l ≤ r < N, compute the sum from A[l] through A[r].

P1 / SPECIFICATION

Define the target relation

Q(A,l,r,y) ⇔ y = ∑ᵢ₌ₗʳ A[i]

The domain requires A to have N integers and valid indices. The output is exactly the specified mathematical sum.

P2 / PROCEDURE

Build a prefix accumulator

pref[0] = 0
for i = 0, …, N−1:
    pref[i+1] = pref[i] + A[i]
return pref[r+1] − pref[l]
C / CORRECTNESS

Establish invariant, termination, and postcondition

Invariant: after processing k elements, pref[k] equals their sum.

Initialization: pref[0] = 0 equals the empty sum.

Preservation: adding A[k] to a correct pref[k] produces the sum of the first k+1 elements.

Termination: the loop has exactly N iterations and N is finite.

Exit: pref[r+1] contains all terms through r; pref[l] contains the terms before l. Subtraction yields precisely Q.

K / COMPLEXITY

Quantify resources

Prefix construction: O(N) time and O(N) extra space. Each query: O(1) time and no additional asymptotic storage. For M queries: O(N+M) total time on a unit-cost RAM model. Choose a sufficiently wide numeric type for implementation.

Proof clinic: identify the missing reasoning

CLAIM A

“Greedy is globally optimal because I pick the locally best choice.”

Local optimality does not imply global optimality without a separate proof. Establish a valid exchange step or another structural argument.

CLAIM B

“The invariant is preserved, so total correctness follows.”

Also prove initialization, that invariant plus exit yields the postcondition, and termination. Preservation alone is insufficient.
